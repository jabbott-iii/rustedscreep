# Tuning guide (SPEC §6.5)

This guide mirrors `crates/rustedscreep-core/src/config.rs` field for field, and a doc-sync test fails when the two diverge.
Each row gives the default (the `mmo` profile's value), the unit, the rationale (with a measurement or source), the safe range,
the runtime key, and the other server profiles whose value differs.

- **Safe range.** The cell starts with the code's range (`config::FIELDS`), which runtime overrides are clamped to. A constraint
  between two fields (`config::RULES`) is stated after it and names the other field; an override that breaks one is refused.
- **Runtime key.** The key for `rustedscreep.configSet(key, value)` (P1.10), or `none` where only a profile sets the value: the
  loader's values are built into the bundle, and the profiler's values and the segment ids are fixed for a global, and a gate's target (`MiningConfig::harvest_efficiency_pct`) is read by no tick. Overrides take
  effect on the next tick, are kept in `PersistConfig::config_segment` across global resets, and load a tick or two after a global
  starts (with the Standard tier; until then, and while the bucket is below the Standard gate, the profile's values apply).
  `rustedscreep.config()` lists every key with the value in force, `configUnset(key)` and `configReset()` remove overrides.
- **Profile overrides.** Each other profile in `config::PROFILES` whose value differs, as `name: value`; `none` while `mmo` is the
  only profile (the optional tracks add `private` in PS1 and `season` in SE2).

| `SchedulerConfig::tick_reserve_pct` | 10 | percent | The engine kills a tick with a wall-clock timeout at tickLimit + 5 ms (at least 30 ms; V105), but the scheduler's clock is isolate CPU time plus intent CPU (V106), and nothing reconciles the two. That is a necessary condition only: it gives the whole reserve to billed calls and counts no free ones, so the safe cost per call is lower. Unverified until a `profiler` build measures the act step on the MMO (`act per call` in `rustedscreep.profiler()`, `act.net / act.calls` against `callBound` in the stats segment, both net of the profiler's own reading; module 8, live number pending). - Opening (P2.4): the worker cap and the recovery count, the wait before a request spawns smaller, the least energy worth scavenging, the downgrade guard, the upgraders kept while building and the stall report are above.
