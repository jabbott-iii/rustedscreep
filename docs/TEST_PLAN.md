# Test plan (SPEC §6.4)

## 1. Unit and property tests (native, `cargo test -p rustedscreep-core -p rustedscreep-consts`)
_Per module._ The list of suites, what each asserts, and how expected values derive from constants.
- `rustedscreep-consts` (P1.2): the native smoke test (room names parse and print, ADR-005); `RoomXY` bounds from `ROOM_SIZE` and `ROOM_AREA`; the cost-matrix (column-major) and terrain (row-major) layouts; terrain bytes decoding from the `Terrain` discriminants with wall precedence; the packed-position round trip; compile-time invariants between `MEMORY_SEGMENT_ACTIVE_LIMIT` and `extra::MEMORY_SEGMENT_COUNT`, and between `CPU_TICK_LIMIT_MAX`, `PIXEL_CPU_COST`, `INTENT_CPU_COST` and `CPU_BUCKET_MAX`; a compile-time check that the API enums and grouped modules are reachable at the crate root; and three compile_fail doctests that keep `look::LookResult`, `FindConstant` and `find::HOSTILE_CREEPS` unreachable (V89). Native tests must never create a `JsValue` or call a JS-backed method (V86). Creating or converting a `JsValue` (`JsValue::from_str`, a `RoomName` into `JsValue`) panics inside a function that cannot unwind, which aborts the whole test binary with SIGABRT and no results. Calling a wasm-bindgen import such as `Position::look()` panics normally and fails only that test.
- `rustedscreep-core::snapshot` (P1.5): `TickContext::from_raw` passes every value of the driver's formula through unchanged (limits × buckets from `CPU_TICK_LIMIT_MAX` and `CPU_BUCKET_MAX`; V37) and clamps the simulator's Infinity, values above the cap, fractions, negatives, NaN and out-of-range buckets; `ObjectKey::from_hex` packs like `RawObjectId` (`(value << 32) | len`, V103), keeps leading zeros distinct, and rejects empty, over-24-digit, uppercase, signed and non-hex ids; the interner keeps a handle while its id is pushed on consecutive passes, releases it on the first pass without it, reuses free slots oldest first with a new generation, detects duplicates, runs the static-data reader once per object life and changes nothing when it fails, retires a slot whose generation would wrap, survives the pass counter wrapping, and keeps its invariants under 500 passes of seeded random churn; `parse_room_name` (P1.7 follow-up, V114) gives the crate's `RoomName::from_str` result on all 65536 canonical names in both cases (each printing back to itself), about 60 edge cases (signs, leading zeros, overflow, bounds, multi-byte characters, `sim`, misplaced letters) and 200000 seeded random strings, half of them name-shaped, with over 10000 that parse, and refuses `i32::MIN` under W or N, where the crate's test build would panic; `extra::HALF_WORLD_SIZE` matches the crate's packed layout at both ends; `position_from_packed` accepts exactly x, y < `ROOM_SIZE` (so `Position::from_packed` never asserts), decodes all 65536 room values to names that parse back, and decodes the engine's worked examples W1N1 and E0S0 (V103); `known_structure_type` passes all 21 known variants and rejects the hidden `__Invalid`; `Controller::from_parts`; row and handle alignment in each table; `key_of` for a sort order that survives a reset; and a scripted four-tick world through the same calls rustedscreep-wasm makes.

- `rustedscreep-core::scheduler` (P1.6): the budget keeps the reserve below tickLimit for limits × buckets from `CPU_TICK_LIMIT_MAX` and `CPU_BUCKET_MAX` (tickLimit from the driver's formula, V37), gives the stated reserve at a low bucket (where ceiling + reserve = bucket + limit), runs Critical at an empty bucket, switches Standard on exactly at its minimum, keeps Optional off for the warm-up loops of a new global, follows the surplus formula at and around the target (the cap equals the limit there), is monotone in the bucket over all 10001 values, runs only Critical for an unlimited user (limit 0, bucket 0, Infinity tickLimit; PS1 handles it), reads a zero spread as 1, and stays safe with an out-of-range reserve; the config is coherent (gates ordered, Standard's gate at least the loader's boot gate plus `CPU_TICK_LIMIT_MAX`, warm-up and break threshold at least 1) and TUNING.md mirrors it; the slicer runs every unit in order when the budget allows (with the expected clock samples), ends a round that lands on a batch boundary as Done with no extra read (also when its last unit crosses the cap), resumes round robin under a tight cap so every unit is visited evenly across ticks with an overshoot of at most one unit, leaves the cursor where a full round started, keeps a cost jump of up to 4 times (stale since the last tick or in the middle of a call) within half the reserve plus one unit at a full and an empty bucket, re-measures on the first unit of a call so a 10-times stale estimate passes the cap by at most one unit, skips the clock read for a job that starts at its cap, isolates a failing unit (recorded with job name, tick and unit) through `run_units` and `isolate`, runs nothing and reads no clock when the tier is off, keeps `remaining` at 0 or above, resumes a step job across ticks and stops it on a fault, counts committed intent CPU (`INTENT_CPU_COST`) against the cap and in the tick record, sanitizes the clock (a lower reading, an infinite one, one NaN, then a negative one that breaks it; the threshold from the config), ignores negative and NaN commits, counts tier-order breaches while still running the late job, and moves the cost estimate up at once and down halfway; the fault log rate-limits reports per window with one suppression note per window that names the held-back jobs (up to 4, then "more"), stays bounded when never drained, closes its window on long jumps and on time falling before its start, and `Scheduler::begin` rotates it; the sleep wheel wakes items exactly at their tick inside and beyond the ring, wakes everything due in wake order across a jump, wakes heap ties in sleep order, never double-fires on a repeated tick, wakes everyone when time goes back, wakes event sleepers early and only once, replaces a sleep on re-sleep and cancels silently, handles sleeps made before the first advance, keeps its heap's peak bounded under churn, reuses emptied event lists (after a fire or a cancel), keeps every recorded event position right when sleepers sharing an event leave in any order, and matches a naive model (as sets per advance) over 20000 seeded random operations with its internal links checked after each; a doctest runs one job end to end.
- `rustedscreep-core::intents` (P1.7): the action list follows the engine's `creepActions` order (V45) with one bit each; the blocking table equals the engine's `priorities` transcribed name for name (V44); heal is never blocked (it blocks seven, V44), and the 13 outside actions are never blocked and block nothing (V46); `ActionSet::executed` matches the engine's rule written over names on all 1024 subsets of the table's ten actions, with and without the outside ones, and on every subset of the ten plus three outside actions it returns a subset that runs whole when issued alone, keeps heal and the outside actions, and is non-empty for a non-empty set; `PRIORITY_ORDER` lists every action once with every blocker before what it blocks and the outside actions in processing order; on every subset of the ten plus three outside actions `ActionSet::kept` is a subset that runs whole, contains `executed`, leaves out only actions with a kept blocker, and differs from `executed` on some sets; the V56 combinations hold, including that a recorded rangedHeal still blocks rangedAttack while the act layer issues heal and rangedAttack; only say and pull are free (`INTENT_CPU_COST` otherwise, V34); `Outcome::from_return` maps 0 to OK, each `ErrorCode` to itself, and NaN, infinities, fractions, positives, -13 and out-of-range values to unknown, only OK and unknown count as recorded, and each code's name is its variant's in words; the buffer commits `INTENT_CPU_COST` per new non-free push and nothing for a replacement or a free method, issues only the last push of a method (a move by direction and a move toward a creep share the slot), refuses every reason but `closed` at least once with the API behavior it stands for (gone, hostile or spawning actor; gone or spawning target; a self-pull, self-transfer or move toward itself; a transfer or withdraw on a controller or a storeless observer, a withdraw from a nuker or power bank, a repair of a controller or power bank, an upgrade of a spawn; targets out of range, including a creep in the next room at world distance 1; an amount of 0 for drop, transfer and withdraw; V108, V109, V113) without committing or replacing anything, accepts a heal of a hostile, a self-heal and range-3 calls, is closed before `begin`, after `resolve` and for a snapshot of another tick or creep count; the issue walk skips what an accepted blocker blocks, issues what a refused, thrown or missing blocker would have blocked, treats an unknown return as recorded, counts blocked and missing intents, and lets a refused billed no-op (a heal of a spawning creep) block nothing; all 120 orders of five pushes give the same calls; over 2000 seeded random ticks the buffer's accept or refuse matches a model that judges each push from the world's facts, and its calls (with target rows) match the model's last accepted push per creep and method, kept in priority order; it keeps its capacity in steady state; `within` needs the same room; `SayText` keeps `CREEP_SAY_MAX_LENGTH` UTF-16 units (asserted equal to the processor's 10) without splitting a character; `ActLog` counts outcomes and missing issues, bills only OK calls of non-free methods, keeps the last failure, and adds each tick to totals that survive `begin`; a doctest issues one replaced move end to end.
- `rustedscreep-core::profiler` (P1.8): `micro` rounding, saturation and refusal of NaN, infinite and negative readings; each series reads only the readings it needs (a NaN or negative reading spoils its neighbours, a falling one is bad); `SeriesStats::of` against a naive sort on edge cases and 2000 seeded lists (exact sum, mean rounded half up, nearest-rank p95 and its rank property); `act_call_bound` from `INTENT_CPU_COST` and `tick_reserve_pct` (tight to 1 µCPU over 5 to 50%, and no division by 0 at 100% or more); the cold loop kept apart, windows closing at exactly `window_loops`, gaps, the bucket range, the act net (act minus clock minus 0.2 per billed intent, good loops with calls only) and the bounded history; 3018 seeded loops with bad readings, skipped ticks and calls against a naive window model; the segment text pinned, its windows, buckets, stats and `lastFlush: null` checked on 25-loop windows, and its worst case (32 windows, every number at its longest) ASCII and within `MEMORY_SEGMENT_SIZE_LIMIT`; the console text exact on varied windows (mean, p95 and max, totals, bad readings, the last window's end, closed against kept, a negative cost per call); the TUNING mirror and coherence of `PROFILER_MMO`.
- Tool tests (`npm run test`, node:test, P1.3): the Cargo.lock and `--version` parsers behind the tool pins; CRC-32 against the catalogue check value (0xCBF43926 over "123456789"); the V76 upload budget at its base64 boundary; path containment with `..x` names and symlinks (the stage guards); the bundle checker ignoring comments, strings and property names but rejecting `fetch`, `URL`, `document`, `pathToFileURL`, `import.meta`, ES module syntax and Rollup's `require('u' + 'rl')`; the purity parser with and without the facade; and the smoke harness rejecting TextDecoder use, an unbundled `require` and a missing `exports.loop`. Every `npm run build` ends by running the real bundle in that sandbox for 9 ticks (loops at offsets 1 to 8, since the boot is split). `npm run stage`'s argument rule (js/tools/lib/stage-rules.mjs, P1.7) refuses an act-test build for deploy/ in any spelling of `--features` and allows it into `--out`.

## 2. Benchmarks (native, `cargo bench -p rustedscreep-core`)
_P2 / P4 / P7._ Planner, flow field, and combat sim, with the latest numbers and the machine used.

## 3. Private server (optional track, `docs/ROADMAP_PRIVATE.md`)
_PS1._ screeps-launcher setup (Docker), config.yml mods, world reset, adding the bot user, deploy profile, and
capturing the console and stats to `logs/`. Scenario scripts (PS3): zero-creep recovery, scripted invaders, scripted attacks, dummy bases. Core gates never depend on this section.

## 4. CPU and bucket comparison against the naive baseline
_P2 onward._ Core method (live MMO): short, bucket-gated windows that alternate optimized, naive and optimized at a comparable colony
state. Each window records its tick range, RCL, room count, creep count and intents. The window length and early-stop bucket level are TUNING
values (ROADMAP evidence conventions). PS2 method (optional private track): identical seed and map, the same tick window, the naive mode that runtime config toggles, mean and p95 CPU per tick,
and the bucket trend. Results go in a table per phase.

## 5. Offense tests against a scripted dummy base (optional track, PS3)
_PS3, after P10–P11._ Core evidence for P10–P11 is native scenario tests plus live sorties against user-approved targets. Dummy base layout (towers, ramparts, economy structures), scripted defender behavior, success and abort criteria,
and the siege-breaker scenario with towers: predicted ETK and survival compared with what actually happened.

## 6. Loader robustness
_P1._ `trap-test` loop, aborted-tick simulation, compile failure, corrupt segments, and missing Memory.
- Unit (js/test/loader.test.mjs, a fake runtime where a halt starts a new Loader on the same Memory): the bucket gate and its log throttle, the split and unsplit boot, the CRC-32 check and its once-per-global notice, a trap and an aborted tick each giving one incident and a halt, compile failures starting backoff at the third in a row, the doubling and capped delay, a persistent trap whose boot gaps grow to the cap, a new streak after a quiet spell, future-dated incidents ignored, a 10-trap trap-test run (3 ticks each, no backoff, one summary), reinstantiate mode and its cap, a failing reset, the no-halt fallback, retries after the cap window, the running flag around instantiation and reset, the record sanitizer against every malformed shape, and no Memory reads on steady-state ticks.
- Unit, snapshot command (P1.5): `rustedscreep.snapshot()` reports a missing export, refuses while the loader is idle or poisoned, calls the wasm only when ready, and a throw from it poisons the instance like a trap in loop (one incident, a halt on the next tick).
- Unit, act and say commands (P1.7): `rustedscreep.act()` and `rustedscreep.say(text)` share the same guard (missing export, idle, poisoned, a throw poisons and the next tick halts); say passes only a string to the wasm and refuses anything else; every console command refuses while the wasm is running, without calling it.
- Unit, scheduler command (P1.6): `rustedscreep.scheduler()` shares the snapshot command's guard (missing export, idle, poisoned, a throw poisons and the next tick halts), and each command checks its own export.
- Sandbox fake world (P1.5, js/tools/lib/world.mjs, following V101 and V103): Game.creeps, Game.rooms and Game.structures per tick, with engine-layout `__packedPos` as signed int32s (worked examples asserted), a neutral controller whose `my` is undefined, a highway room (E0S0) without a controller whose positions are negative, a spawning creep, a hostile Invader, a creep with a non-hex id and a structure of an unknown type. Every build's smoke test runs the real wasm against it and checks two `rustedscreep.snapshot()` lines: each room's controller and its creep and structure counts (from decoded positions), table sizes, the spawning count, handle churn (new, gone, live), the two skips, and that the JS objects stay aligned with the rows. Each fake creep has the ten action methods the act layer binds, which record the call and return a scripted value, and from offset 6 a second Invader stands in W1N1 (P1.7). The smoke test sends `rustedscreep.say(42)`, which the loader refuses, and later `rustedscreep.say("hi")`, and checks that exactly the two own creeps that are not spawning get `say('hi', false)` on the next loop, the Invader is not asked, nothing else is called in the 9 ticks (the loop after the say included), and `rustedscreep.act()` reports 2 queued, 1 refused (the spawning creep), 2 issued, 2 OK and 0 billed. It also checks two `rustedscreep.scheduler()` lines (P1.6): on the first loop the ceiling 450.0, Standard on and Optional off for warm-up, with no clock samples, units or faults; on the fourth loop Optional on with cap 30.0 (from `SCHEDULER_MMO` at limit 20, tickLimit 500, bucket 10000); each with a clock reading through the real `Game.cpu.getUsed` binding; and no fault lines.
- Unit, profiler command (P1.8): `rustedscreep.profiler()` shares the guard (missing export, idle, poisoned, a throw poisons and the next tick halts).
- Sandbox, segment save (P1.8, js/tools/smoke.mjs `saveSegments`, following V41 and V85): every key of `RawMemory.segments` is saved at the end of the tick, and a save with more than 10 keys, an id outside 0-99, a value that is not a string or one over 100 × 1024 characters stores nothing (unit-tested at both limits). Every build's smoke run counts the loop's `getUsed` calls once booted (0 without the profiler, 6 with it) and its `RawMemory.segments` reads (none in 9 ticks).
- Sandbox, profiler build (P1.8, js/tools/profiler-sim.mjs, row 12 of `npm run check`): six 1000-loop windows; the cold line once; 6 `getUsed` calls per loop and 7 on a closing one, which alone reads `RawMemory.segments`; the first two writes saved and parsed as the documented JSON (header, cold loop, two windows with every series' n, bad, ordering, buckets and the say's calls); a say that the game refuses once still counts both calls; the four guarded failures (no RawMemory, segments not an object, a set that throws, a frozen object) each one log line with the segment left as it was; `rustedscreep.profiler()` at four points.
- Sandbox, act-test build (P1.7, js/tools/act-sim.mjs, row 11 of `npm run check`): the `act-test` feature's scripted producer (rustedscreep-wasm `act_test.rs`) queues every variant, a replaced move, heal blocking rangedHeal and repair, rangedHeal blocking repair, and one push for each refusal reason but `closed` as soon as the scene allows it (zero amount, wrong target and not in range every tick; not mine at offsets 2, 3 and 6; spawning and spawning target from 3; gone target and gone actor from 4), in a scene that puts every target in range but one far extension. For 6 loops the harness checks every JS call (method, actor, arguments: targets by object, the resource as its string, `undefined` for an omitted amount, `true` for a public say, a creep for a move toward it) by row and blockers first; that an accepted heal or rangedHeal skips what it blocks while b's rangedHeal refused on even ticks lets its repair be called; the classification of the scripted returns (OK, ERR_FULL, ERR_NOT_ENOUGH_RESOURCES, ERR_NOT_IN_RANGE, an `undefined` counted unknown); a tick on which every method throws (13 calls, all caught, nothing skipped); the 10 rate-limited fault lines with no incident or halt; and three `rustedscreep.act()` lines with their totals. `npm run stage` refuses an act-test build for deploy/.
- Sandbox, real bundle (js/tools/smoke.mjs and trap-sim.mjs, following the open-source runtime as V96 records it): every build boots and runs; the harness also models a halt discarding Memory and a null Memory after invalid JSON; `npm run check` builds two trap-test variants and runs 10 forced traps through the panic hook, the polyfill and each recovery mode. Corrupt segments arrive with persistence (P1 module 9); on the MMO the P1 gate repeats the 10-trap test.

## 7. Native scenario tests (core)
_P2 onward._ Pure-Rust scenario tests in `rustedscreep-core` that stand in for in-game scenarios on the core track: zero-creep recovery
(P2), remote abandon and evacuation (P6), combat scenarios against tower and defender configurations (P7), offense state machine with an

## 8. Live MMO checks (core)
_P1 onward._ Deploys reach the MMO when the user pushes the staged `deploy/` folder through the GitHub link (ADR-012); P1 first verifies that path (VERIFICATION_LOG V77). Snapshot (P1.5): after the first live boot, `rustedscreep.snapshot()` in the console must show the shard's CPU limit, tickLimit and bucket, the owned room, every own creep and structure, `skipped 0`, and steady handles (`new 0, gone 0`) on a quiet tick. Scheduler (P1.6): `rustedscreep.scheduler()` must show a loop count that grows by one per tick within a global, the caps the formula gives for the shard's limit, tickLimit and bucket at that tick (TUNING.md; Optional off below 7000 at the free tier), a `clock now` reading below the ceiling, and `faults since boot 0`. The first-loop warm-up is covered by the smoke test, since a console command cannot be timed to the first tick. Act layer (P1.7): `rustedscreep.say("hi")`, then `rustedscreep.act()` on the next tick, must show queued = the own creeps that are not spawning, refused (spawning) = the spawning ones, issued = ok = queued, billed 0 (say is free, V34), and no faults (later ticks keep them in the totals since boot); the bubbles are visible to the owner only. This is the only intent the P1 bundle issues. Profiler (P1.8): a build staged with `npm run stage -- --features profiler` (once the user names `mmo`; the `/deploy` skill takes no features yet) logs one `rustedscreep profiler: first loop of this global` line per global, and `rustedscreep.profiler()` must show a growing open window with good readings (no `bad readings`), the `clock` mean (one `getUsed` call), `start` and `end`. `snapshot`, `decide` and `act` each include one `getUsed` call, so a step's own cost is its series minus the `clock` mean. Before `rustedscreep.say("hi")`, check with `rustedscreep.snapshot()` that own creeps that are not spawning exist (the P1 bundle never spawns, and creeps live `CREEP_LIFE_TIME` ticks); if none do, the user spawns one. Then `act per call` covers the say calls, net of the profiler's reading, against the bound (0.0222 CPU, a necessary condition only); it still includes the act step's fixed work per tick, and say calls include a string decode, so it reads high with few calls; billed intents first arrive in P2. After 1001 loops, segment 99 holds the first window: read it with `npm run stats` once item 3b exists, or, while nothing else uses segments, with `RawMemory.setActiveSegments([99])` and `RawMemory.segments[99]` on the next tick; before using it as evidence, match its `cold.time` with the boot log line's `Game.time`, since the segment outlives a deploy. The loop's CPU floor is the `end` series (mean and p95 over a window) from a profiler-only build, minus the profiler's five earlier readings (about 5 × the `clock` mean); billing adds up to 1 CPU more (ceil, V106). Cold start for the boot gate is measured with the plain build, since the profiler build's wasm is larger (96732 against 62063 B at P1.8). What each core gate observes on the official MMO, how it is captured (`npm run console` and `npm run stats` into `logs/`),
and which checks need the user's approval first (live offense sorties in P10 and P11).
