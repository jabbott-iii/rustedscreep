# Test plan (SPEC §6.4)

## 1. Unit and property tests (native, `cargo test -p rustedscreep-core -p rustedscreep-consts`)
_Per module._ The list of suites, what each asserts, and how expected values derive from constants.
- `rustedscreep-consts` (P1.2, the constants facade: the crate the rest of the code reads the game's constants through): the native smoke test (room names parse and print, as ADR-005 requires: that architecture decision record (ADR) has this crate re-export `screeps-game-api`'s constants, so it must build and run natively); `RoomXY` bounds from `ROOM_SIZE` and `ROOM_AREA`; the cost-matrix (column-major) and terrain (row-major) layouts; terrain bytes decoding from the `Terrain` discriminants with wall precedence; the packed-position round trip; compile-time invariants between `MEMORY_SEGMENT_ACTIVE_LIMIT` and `extra::MEMORY_SEGMENT_COUNT`, and between `CPU_TICK_LIMIT_MAX`, `PIXEL_CPU_COST`, `INTENT_CPU_COST`, and `CPU_BUCKET_MAX`; a compile-time check that the API enums and grouped modules are reachable at the crate root; and three compile_fail doctests (documentation examples that pass only if they fail to compile) that keep `look::LookResult`, `FindConstant`, and `find::HOSTILE_CREEPS` unreachable (V89: they carry JavaScript (JS) handles, so they are not pure). Native tests must never create a `JsValue` (a handle to a JS value) or call a JS-backed method (V86: which `screeps::local` items are pure, JS-backed, or panicking). Creating or converting a `JsValue` (`JsValue::from_str`, a `RoomName` into `JsValue`) panics inside a function that cannot unwind, which aborts the whole test binary with SIGABRT (the abort signal) and no results. Calling a wasm-bindgen import (a JS function bound for the WebAssembly, or wasm, build) such as `Position::look()` panics normally and fails only that test.

## 4. CPU and bucket comparison against the naive baseline
_P2 onward._ Core method (live MMO): short, bucket-gated windows that alternate optimized, naive, and optimized at a comparable colony
state. Each window records its tick range, RCL, room count, creep count, and intents. The window length and early-stop bucket level are TUNING
values (ROADMAP evidence conventions): `CacheConfig::naive_max_ticks` (1000, one profiler window) and `CacheConfig::naive_stop_bucket` (8000),
which the bot enforces itself by removing the cache overrides (ADR-022). Procedure: on the last tick of an optimized profiler window (in a global
without gaps a window's `last` is `cold.time` plus a multiple of `ProfilerConfig::window_loops`), turn the three caches off in one console entry that also prints `Game.time`:
`[Game.time, ...['cache.structure_static', 'cache.movement_grid', 'cache.flow_fields'].map(k => rustedscreep.configSet(k, 'false'))].join('\n')`.
Console commands run after the loop (V118), so the next loop is the span's first, and the guard ends it after 1000 ticks with the line
`rustedscreep config: naive baseline ended after 1000 ticks ..., ticks S to L`, which gives the span's exact range; `rustedscreep.config()`
shows a running span. A span set a tick late leaves a few cached loops at the start of the naive window and as many naive ones in the next;
the span's range from the log line counts them.
To start at any tick instead, set the length in the same entry so the span ends on the last tick of the first whole window after it
(a `configSet` applies to the store at once and the guard reads the length on every loop; config-sim sets it before the caches); with C the
global's `cold.time` (in a global with a gap since its cold loop, C = F − 1 for F the open window's first tick in `rustedscreep.profiler()`) and W `window_loops` (1000), the length is E − T (the end line then shows it in place of 1000) for E = C + W × ⌈(T − C + W) / W⌉, between W and 2W − 1:
`(() => { const C = <cold.time>, T = Game.time, E = C + 1000 * Math.ceil((T - C + 1000) / 1000); return [T, E - 999, E, rustedscreep.configSet('cache.naive_max_ticks', String(E - T)), ...['cache.structure_static', 'cache.movement_grid', 'cache.flow_fields'].map(k => rustedscreep.configSet(k, 'false'))].join('\n'); })()`.
The window before E − 999 is then mixed and is not used. Remove the length with `rustedscreep.configUnset('cache.naive_max_ticks')` (the guard
removes only the cache overrides) on console tick E + 1000 or later, once the optimized window after the naive one has closed: an unset before L
shortens the span to W ticks, and one before E + 1000 writes the record inside that window. The ADR-022 build's first span (V208) was set on
84305517, 1400 ticks after the planned 84304117 (400 after window 3 closed), and left two mixed windows.
Take `[Game.time, level, progress]`, `Object.keys(Game.creeps).length`, and `rustedscreep.opening()` once inside each of the three windows (the
segment holds only the ticks and the intents), and keep the spawn lines of all three: a creep name gives its order's tick
(Game.time × 256 + index), and a window that holds a worker generation's turnover (workers being the general-purpose creeps that harvest, fill, build, and upgrade) bills fewer intents, since a spawn's energy is not
upgraded (V210). Give the orders per window with the result. Push nothing to `main` from the span's start until segment 99 has been read: any push reloads the
code (V145). If the end line was missed, `rustedscreep.config()` shows the record `written at tick L`: the stop's flush writes it on L when L
runs the Standard tier.
The window counts as the naive window only when it lies within the line's S to L and its last tick is L (a whole profiler window
of naive loops, ADR-022), with the optimized ones around it: the window after it and, before it, the last window that ends before S, each with no naive loop; otherwise
run the procedure again on a later window. Run it again too if the bucket ends the span (the warning `rustedscreep config: naive baseline ended early at bucket B ...`), if a
global reset comes during the span (the loops before the record's load run cached) or before the optimized window after it closes (that window is
then never written), or if another config change is written during it. The end
line is at info level, so keep `log.level` at info (the profile's value) for the run. The PS2 method (private-server baselines, an optional track): identical seed and map, the same tick window, the naive mode that runtime config toggles, mean and p95 CPU per tick,
and the bucket trend. Results go in a table per phase.

Remote mining (P6.2, ADR-029): what to look for after the deploy.
- **Scouting.** Within a few hundred ticks `rustedscreep.spawner()` shows a scout request (one MOVE part, 50 energy), and a creep named `sE7N57<room>-…` walks into an exit neighbor. `rustedscreep.remote()` then lists each neighbor as `seen N ago (S sources)`, or `not minable` for a room another player holds or reserves, or one with an invader core. The scout calls `suicide` once every neighbor is seen and each minable one shows a plan.
- **Choosing a room.** A priced neighbor shows `[reserve, roads, net X/tick, cpu Y, spawn Z per mille]`, and up to `remote.max_rooms` of them show `mined`. The spawner then shows reserver, remote miner, and remote hauler requests (names `r`, `n`, `c` with the home and the remote room). These come only after the home's own requests.
- **Running it.** Within a reserver's walk the mined room's line shows `reserved T`, with T climbing and never past 5000 (no reserve call goes out past the cap, V264). A container site appears on each mining tile and the miner builds it. Haulers bring full loads home and deliver them as the home's own haulers do: the spawns and extensions first, then the controller container. Under a roads plan, road sites appear along each way (`sites placed P` in the remote line) and the haulers build them.
- **Upgraders.** The home's `upgrading:` budget rises by about the room's net while one of its haulers lives.
- **Threats and contests (P6.3).** When armed hostiles enter a mined room, the log shows `rustedscreep remote: <room> (of <home>) threatened by N armed hostile creep(s) of <owners> (A ATTACK, R RANGED_ATTACK parts); its creeps wait in <home> until tick T`, and the remote line shows `threatened (N armed) until T`. Its creeps then walk home and no remote request goes out. At T the log shows `... the wait is over, its creeps go back`. A room another user comes to reserve, or one with an invader core, logs `abandoned (contested) until tick T`; its miners and reserver end (a `suicide` each), and its haulers come home first.
- **The P6 gate's reading.** ADR-031 (the reading waits for a remote room the bot can mine) carries it to the first live run in which a home mines a remote room: the spawn log shows `r`, `n`, and `c` names that carry a remote room, and `rustedscreep.remote()` shows `mined`. Net energy per CPU comes from that run: the model's figure in `rustedscreep.remote()`, checked against the home's upgrade progress and `rustedscreep.scheduler()`'s CPU over a few creep lives. - **Controller signer (ADR-030).** Once a home reaches `sign.min_level`, `rustedscreep.sign()` shows the record loaded from segment 95 (`loading` until then) and, a few ticks later, `plan ready from <home> for <home> (1 parts, 50 energy)`.
